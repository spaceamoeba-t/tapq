# TapQ Experience Roadmap

This document describes TapQ's **user-experience direction**. It complements the repository's technical [`docs/ROADMAP.md`](../ROADMAP.md), which tracks engineering capabilities and integrations.

No dates in this document are release commitments.

## Now — Developer Agent Mode

**Status: Available / evolving**

TapQ's first use case is hands-free supervision of AI coding agents.

The experience proves the core loop:

> AI needs attention → TapQ reaches the user → user responds by voice or motion → AI keeps working.

Current product focus includes:

- Claude Code, Codex, Cursor, and OpenCode integration,
- spoken agent prompts,
- AirPods head-motion controls,
- voice responses and follow-up instructions,
- wearer attribution,
- graceful return to the on-screen workflow when needed.

## Next — Business Mode

**Status: Planned / highest-priority experience expansion**

Extend TapQ from AI-agent supervision to real-time assistance in professional conversations.

Product direction:

- explicit meeting sessions,
- contextual understanding of the conversation,
- private clarification of unfamiliar terms,
- nod/shake interaction for assistance,
- concise in-ear responses,
- structured post-meeting notes and recall.

The defining experience is not simply recording a meeting. It is **helping the user understand it while it is happening.**

[Business Mode →](BUSINESS_MODE.md)

## Then — Lecture Mode

**Status: Planned**

Adapt the same session/context layer for academic learning.

Product direction:

- contextual explanations during class,
- mark-for-review interactions,
- structured lecture notes,
- concepts and definitions,
- post-class summaries and unresolved questions.

[Lecture Mode →](LECTURE_MODE.md)

## Later — Travel Mode

**Status: Vision**

Combine translation with contextual AI assistance rather than compete on translation alone.

Product direction:

- translated conversations through earbuds,
- contextual interpretation,
- hands-free follow-up questions,
- generated replies in the local language.

[Travel Mode →](TRAVEL_MODE.md)

## Across every mode

Several principles should remain consistent as TapQ grows:

- **use hardware people already own,**
- **keep assistance private when possible,**
- **reduce screen dependence,**
- **prefer context-aware answers over generic responses,**
- **keep the human in control,**
- **make failure safe and visible.**

The long-term direction is broader than AirPods or coding agents:

> **TapQ aims to become the interaction layer between people, their everyday wearables, and their AI agents.**
