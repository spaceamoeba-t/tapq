# Lecture Mode

**Status: Planned**

> **Stay with the lecture, even when one idea does not click immediately.**

Lecture Mode applies TapQ's context-aware, hands-free interaction model to learning.

## The problem

In a lecture, one unclear concept can create a chain reaction. A student searches for a definition, rereads slides, or asks a chatbot — and misses what the professor says next.

TapQ is exploring an experience where students can ask for help without leaving the lecture.

## During class

With Lecture Mode explicitly enabled, TapQ could maintain the current lecture context and let the student discreetly request help.

Examples:

- “Explain that concept.”
- “What does this term mean here?”
- “Mark this for review.”
- nod to accept a short explanation,
- shake to dismiss a proactive offer.

Explanations should be brief enough that the student can return attention to the professor quickly.

## After class

TapQ could organize the session into:

- key concepts,
- structured notes,
- important definitions,
- formulas or frameworks discussed,
- concepts the student marked as unclear,
- unresolved questions,
- a short review summary.

The goal is not to replace note-taking or the professor. It is to reduce the cost of **losing the thread** when something is unclear.

## Built from the same interaction layer

Lecture Mode reuses the same foundation as Business Mode:

**session context → private AI assistance → subtle user input → useful post-session memory**

That shared foundation allows TapQ to support different environments without requiring a different wearable for each one.

## Privacy

Lecture capture must be explicitly enabled and should respect institutional rules, accessibility policies, instructor preferences, and applicable recording laws.
